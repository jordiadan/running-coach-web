# Running Coach web

React, TypeScript, Vite and Tailwind frontend. See [AGENTS.md](AGENTS.md) for
working conventions, [PRODUCT.md](PRODUCT.md) for source-backed product context
and open decisions, and [DESIGN.md](DESIGN.md) for the existing visual system.

```sh
npm install
npm run dev
npm run lint
npm test
npm run build
```

## Impeccable in Codex

Reuse the global skill at `~/.agents/skills/impeccable`; this setup was verified
with skill 4.5.0 and engine 0.1.11. No local copy or npm dependency is required.
If missing, follow the [official installation guide](https://impeccable.style/tutorials/getting-started/)
for a global Codex installation, then restart Codex.

Skill commands run in the chat:

- `$impeccable init`: update product facts and explicitly unresolved decisions.
- `$impeccable document`: refresh DESIGN.md and `.impeccable/design.json` from
  the existing system.
- `$impeccable hooks status`: inspect detector configuration.
- `$impeccable doctor`: check setup/schema drift.

The underlying launcher also supports these configuration checks in a terminal:

```sh
"$HOME/.agents/skills/impeccable/scripts/impeccable" hooks status
"$HOME/.agents/skills/impeccable/scripts/impeccable" doctor --json
```

`.codex/hooks.json` registers one PostToolUse detector for direct edits and one
Stop pass for deferred findings. It calls the global launcher using `$HOME` on
macOS/Linux; if the skill is missing, the command skips execution. Windows needs
a manifest generated by the official installer for that environment. Shell-based
file writes are outside this manifest's direct-edit matcher.

Open `/hooks` in Codex to review and trust the exact loaded definitions.
[Hook trust is stored per definition](https://learn.chatgpt.com/docs/hooks);
a changed command or a new clone can require approval again. Impeccable's
`hook.consent` does not grant Codex trust. The checked local installation's
hooks were trusted; that approval is not shipped with this portable manifest.

Codex 0.161.0 loaded project hooks from the main checkout's `.codex/` when
inspecting its Git worktree, rather than from the worktree's manifest.
Check the source shown in `/hooks`; do not assume a worktree tests its own file.

Keep one Impeccable detector per event across active user/global, project and
plugin sources. The setup check found no global Impeccable detector; Warp's
hooks are separate. If another machine has a global detector, choose one source
in `/hooks` rather than enabling both.

Shared configuration and the design sidecar are tracked. Local overrides,
consent, caches, screenshots and sessions are gitignored.
`.impeccable/live/config.json` targets `index.html`; the initial source check
found no CSP. Live Mode is configured without starting its helper, injecting
scripts or changing CSP. No construction preference (`buildPath`) is stored;
ask before persisting one when a future design task needs it.

Validation covered a real Codex `apply_patch` event on a temporary fixture,
the committed commands with Codex-shaped PostToolUse/Stop inputs, deferred
finding deduplication and the disabled override. No product UI was audited.
